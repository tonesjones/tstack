# Skill friction proposals, 2026-10-25

These are proposed edits to tstack skills, drawn from Claude Code transcripts and
the vault. Nothing here has been applied, and no `SKILL.md` was edited. Tony
reviews each row and picks the ones to apply.

## How this was made

- **Source.** Every `Skill` tool call and slash command for a tstack skill in
  `~/.claude/projects/**/*.jsonl`, found with the same matching as
  `.tools/skills/skills_catalog.py`. Skill-creator trigger-eval runs (`trig-*`,
  `tmp-*` folders) were left out. Subagent transcripts were included.
- **Review.** Sonnet subagents read a condensed log of each invocation and the
  turns after it. I checked the themes kept here against the excerpts and the
  current skill text on `origin/main` (shutdown-when-done against PR #12's
  branch, since it isn't on main yet).
- **Vault.** `40 Sessions/` notes, the tstack hub, and `50 Claude/Memory/tstack/`.
  Nothing was read from `95 Private/`.
- **Bar.** A row is kept only when the problem showed up in 2 or more sessions
  or Tony corrected it, and the current skill doesn't already cover it.
- **Limits.** The subagents mostly read the first 10 to 30 events after each
  invocation, so friction late in a long session may be missing. Session ids
  below are the first 8 characters of the transcript file name.

## deslop

### 1. Diff against a fetched `origin/main` (Gotcha or body edit)

Replace the first bullet under "Get the diff" with:

> - **Git repo with a shell.** Run `git fetch origin` first. Local `main` lags behind
>   squash merges, so a diff against it shows work that already merged. Use
>   `origin/main`, or the remote default branch from `git symbolic-ref
>   refs/remotes/origin/HEAD` if there is no `main`. Diff from the merge base so
>   uncommitted work is included: `git diff $(git merge-base HEAD origin/main)`.
>   List the touched files with `--name-only`.

**Evidence.** In 14 of 68 invocations, the caller had already swapped in
`origin/main` or a worktree base by hand: c979578c (2026-10-04), 2647215a
(2026-10-05), 3835dc7c (2026-10-08), 586da966 and 8d4bc577 (2026-10-20),
3f40741f and 47a75cd6 (2026-10-23), 29da2f51 and d22aa6d2 (2026-10-25). The
tstack memory note `branch-from-origin-main.md` records the same lag.
**Frequency.** 14 invocations in 9 sessions.

## codex-delegate

### 3. Windows console encoding crash (Gotcha, plus a code fix)

Add to Gotchas:

> - **The bridge can crash printing Codex's answer on Windows.** A non-ASCII
>   character in the final message raises an encoding error from the console's
>   code page. The answer is still on disk: read the receipt's `final` path, or
>   rerun with `PYTHONIOENCODING=utf-8`.

Mechanism (backlog, preferred over prose): have `codex_bridge.py` call
`sys.stdout.reconfigure(encoding="utf-8", errors="replace")` at startup. The
bridge reads files as UTF-8 but never reconfigures stdout. With that fix in
place, the Gotcha isn't needed.

**Evidence.** d72519aa (2026-10-06, finding-validation-agent): the bridge
crashed on a Luna answer, and Claude pulled the answer from the log with
`PYTHONIOENCODING=utf-8`. 7827932e (2026-10-24, finding-validation-agent): it
crashed on a Sol answer, and the answer came from the saved final message.
87a652b3 (2026-10-24) used the same workaround. The vault session note
`2026-10-23 Finding Validation Agent PHP CVE lab setup` already proposed
"set `PYTHONIOENCODING=utf-8`" and it is still unreviewed.
**Frequency.** 2 to 3 sessions.

### 8. Read-only reviews can't run file-writing tests (Gotcha)

Add to Gotchas:

> - **Read-only runs can't create temp directories.** In the default read-only
>   sandbox, tests that write files or run the CLI end to end fail or get skipped,
>   and a review can still report "no defects". Treat test results from a
>   read-only run as partial: run those tests yourself, or use `--write` in a scratch
>   worktree.

**Evidence.** 1f1a4b37 (2026-10-20, bball-league-assistant): a Sol review
couldn't run the CLI integration tests but reported no defects. cc504b9c
(2026-10-20, bball-league-assistant): two filesystem tests couldn't finish
because temp directory creation was denied.
**Frequency.** 2 sessions.

## shutdown-when-done (PR #12 branch, not on main)

### 7. Power words in text, not commands, get blocked (Gotcha)

Add to Gotchas:

> - **The gate also matches text that isn't a command.** A power word in a file
>   name, a commit message, or a heredoc body gets the Bash call denied. So does a
>   standalone `-e` in a `.ps1` file. Rename the file, or write the text with the
>   Write tool, rather than retrying the command.

Mechanism (backlog): match power words only in command position (after
`powershell`, `pwsh`, `cmd /c`, or at the start of a pipeline segment). Bash
commands already get this for `-e` (`shutdown_gate.py` line 116). Written script
files don't (line 107).

**Evidence.** e52f5749 (2026-10-25, bball-league-assistant worktree): a vault
`git` command was denied because a note's file name contained the power word,
and Claude renamed the note to commit it. In this audit session (2026-10-25), a
subagent's Python heredoc was blocked because its text contained the word. The
vault note `2026-10-25 airplay-windows native mirroring` records the `-e` false
positive (`git cat-file -e`, `grep -E`) and proposes the same fix.
**Frequency.** 3 sessions.
